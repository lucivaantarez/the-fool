API REFERENCE

ZeroPoint Cookie Checker API

Validate Roblox cookies programmatically — alive / dead / face-lock / captcha-lock / ban-warn. Free to use, no credits.

Overview

The Cookie Checker API lets you submit a batch of Roblox cookies and poll for classification results, the same engine the website uses. It is completely free — there is no balance, no credits, and no payment of any kind.

  • Base URL: https://zeropoint.to/api/cookie-checker-api
  • Auth: every request needs your key in the X-API-Key header.
  • Rate limit: 1 job every 20 seconds per account (shared with the website — submitting on the site counts too).
Your API key is created and managed on the Cookie Checker page (the “API Access” card). It looks like ZP_CookieChecker_…. Keep it secret — anyone with it can submit jobs as you.

Authentication

Send your key on every request:

X-API-Key: ZP_CookieChecker_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

Missing/invalid key → 401. A disabled key → 403.

Endpoints

POST/api/cookie-checker-api/submit

Submit a batch of cookies for checking. Returns a session_id you poll for progress.

Body (JSON)

FieldTypeDescription
cookiesstring | string[]Newline-separated text or an array of lines. Each line is kept only if it contains a ROBLOSECURITY cookie (the _|WARNING… token). Other lines are ignored. The original line is preserved in results.

Example

curl -X POST https://zeropoint.to/api/cookie-checker-api/submit \
  -H "X-API-Key: ZP_CookieChecker_xxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{"cookies":"user:pass:_|WARNING:-DO-NOT-SHARE…\nuser2:pass:_|WARNING:-…"}'

Response

{ "session_id": "a1b2c3d4", "total": 2, "status": "checking" }

400 if no valid cookies. 429 if you submitted within the last 20s ({ "error":"…","cooldown": <seconds> }).

GET/api/cookie-checker-api/status/:sessionId

Poll a job. Only the key that submitted the job can read it (else 404). Poll every ~1–2s.

Response

{
  "status": "checking",            // pending | checking | completed | error
  "total": 100,
  "checked": 42,
  "alive_count": 10, "dead_count": 28,
  "face_lock_count": 2, "captcha_lock_count": 1, "ban_warn_count": 1,
  "download_files": [
    { "type":"alive", "count":10, "filename":"alive_a1b2c3d4.txt",
      "url":"/api/cookie-checker/download/a1b2c3d4/alive" }
  ]
}

When status is pending, a queue_position may be present. Download via the API path below once completed.

GET/api/cookie-checker-api/download/:sessionId/:type

Download a result file (plain text, one entry per line, original format preserved). Ownership-checked. Available once the job is completed.

type

alive · dead · face_lock · captcha_lock · ban_warn

Example

curl -OJ https://zeropoint.to/api/cookie-checker-api/download/a1b2c3d4/alive \
  -H "X-API-Key: ZP_CookieChecker_xxxxxxxx"

Result types

TypeMeaning
aliveCookie is valid and the account is usable.
deadCookie is invalid / expired / logged out.
face_lockAccount is alive but behind a facial-verification lock.
captcha_lockAccount is alive but behind a captcha/account-unlock challenge.
ban_warnAccount is alive but has a moderation ban/warning.
Rate limit: one submit per 20 seconds per account. A 429 tells you how many seconds remain (cooldown). This is shared with the website, so don't submit on both at once.

Errors

CodeMeaning

403API key disabled.
400No valid cookies in the request, or invalid download type.
404Session not found / not yours / expired.
429Rate limited (1 job / 20s).
